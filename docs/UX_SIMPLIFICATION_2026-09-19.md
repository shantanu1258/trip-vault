# Trip Vault — simpler trip experience

Accepted and implemented locally on 19 September 2026. This amendment supersedes the Home-dashboard, separate Agenda, and floating view-switch descriptions in FEATURES, HLD, and LLD. The earlier application review remains a historical backlog, not a claim that all its findings are fixed.

## Decisions

- Primary navigation is **Trips / Vault / Profile**. Global Add is removed. Old `/home` and `/add` URLs redirect to Trips; invitations and joining by code remain available there.
- Trips retains Home's urgent-action reminder as a compact full-card review link above the trip list, with trip context but no large Home hero. It uses the existing focused-trip selection and shared alert cache, including dismissal/snooze filtering; no urgent alert means no card.
- Readiness alerts deep-link to their specific task (`?task=…`), opening its details sheet after loading instead of stopping at the checklist. Closing clears the task parameter without losing return context; missing tasks show an explicit unavailable message rather than a different task.
- Fresh authenticated entry at `/` opens a trip only when exactly one non-archived, non-completed trip is within ten calendar days before departure through its final day, using that trip's timezone. Overlapping windows open Trips for an explicit choice. Direct links and resumed routes are not overridden.
- Timeline and Agenda are one compact, date-grouped view. Dates start open; only the current/next item starts expanded. Opening another card leaves existing cards open.
- A single **Filter timeline** icon holds date selection, Expand/Collapse dates and cards, Reset to next event, the next-event shortcut, and Calendar export. Expanding cards also reveals their dates; expanding dates does not expand their cards. Collapsing dates preserves card choices. Search and next-event navigation clear a conflicting date filter.
- Search and Next event reveal the destination date/card before scrolling. The scroll offset accounts for both sticky headers. Presentation choices survive child-page/tab navigation in session storage, scoped by profile, trip, and traveler; they are not cloud-synced.
- The user's event times remain authoritative, including separate Hotel check-in and checkout milestones. There is no inferred checkout time or new notification service in this change; existing scheduling/reminder behavior remains in place.
- Only the labeled Timeline / Trip details tabs stay sticky. The repeated trip title is removed; search scrolls normally, exists only in Timeline, and is reached through the header search button. Floating controls are only Add event and the selected traveler's name (Everyone when unfiltered). Traveler focus is not account identity.
- Collapsed rows follow the former Agenda's title-first, icon-and-secondary-line layout (66px rows in tested mobile sizes). Long titles/routes truncate in the compact view; expanded cards retain full details and booking/document shortcuts. Readiness tasks are always compact checkbox rows: check to complete/advance, tap the title to open the task modal, with no extra expansion step. The public demo uses the same timeline component.
- Optional form sections share visible disclosure indicators and filled-field counts. Existing values/required fields open their sections; collapsed inputs remain mounted for submission and draft preservation. Native validation reveals an invalid section.
- Timezone fields use a single label with on-demand help; international departure/arrival zones remain distinct. Traveler names are larger beside seats. Optional documents and flight updates use progressive sections without hiding file-sharing defaults inside help.
- Trip details drop redundant eyebrow labels and nested Offline/Airlines cards. Creation copy says **Create a new trip**. Signed-out onboarding is a numbered, non-card sequence.
- Trip details no longer repeat the readiness checklist. Reservation category pills link to their category-filtered reservation list; filters preserve the trip-return context.
- The Reservations page starts with a back icon beside the title, the trip name below, and a compact Add button to the right. Side-by-side search/traveler controls come next, then category filters and booking rows. There is no introductory helper text or separate back-label row.
- Reservations and trip Documents use 4px top padding on mobile instead of 24px, with no extra gap after the back link; its 44px tap area is preserved.
- Form accordions use 10px padding on phones and 16px on larger layouts. Fieldsets and grid children can shrink so long placeholders and picker labels do not push inputs outside their cards.
- PDF.js resolves its public module URL at runtime, preventing Vite from importing the public asset through the source transformation pipeline.
- Jump-to-event highlighting retains two pulses over 900ms on the outer card border only: no glow or content animation from the highlight. The current item's coral border returns afterward; reduced-motion preferences remain respected.
- Expanded event-card bodies are full-area details targets, with a small "View details" text cue instead of a separate large button. Headers still expand/collapse; navigation, document, location-edit, and phone shortcuts remain independent controls above the card target.
- Trip-details section links no longer trigger a competing scroll-to-top on their first click: the global scroll manager resets only on pathname changes, not when an in-page anchor clears history state. Trip-specific restoration remains in TripPage.
- App typography uses locally bundled DM Sans (normal and italic variable weights), with Helvetica/Arial fallbacks, including headings, controls, and previously monospace UI labels. Fontsource supplies the font; its OFL licence is shipped under `public/fonts/DM-Sans-OFL.txt`. WOFF2 assets are included in the existing offline precache. Document/PDF contents retain their original fonts.
- Reservations title and trip subtitle now share one left edge between the back icon and compact Add action, removing the detached subtitle row.
- Mobile app headers use a 56px row instead of 76px: a 32px logo, single-line Trip Vault name, no tagline, and tighter action spacing. Search, alerts, and theme controls keep 44px touch targets. Sticky trip tabs share the responsive header-height variable; larger screens retain the original header branding.
- Mobile bottom navigation uses a compact 56px bar plus the device's safe-area inset, preserving all three labels and 48px-tall touch targets. Floating trip controls use 4px padding, 48px buttons, and an 8px gap above the navigation, sharing its height variable in both live trips and the public demo.
- The floating dock uses 2px padding, compact labels and 48px-high controls. Everyone remains visibly labeled (the request was smaller sizing, not hiding the label); a selected traveler shows their avatar and compact truncated name.
- Mobile timeline removes its redundant outer card/padding and uses a slim vertical rail with dots. Readiness uses a softly tinted dashed checkbox row, an explicit Task label, and no chevron or Next badge; its title still opens the task modal. Following the next review, combined readiness/event priority is restored: the actionable readiness task has an amber solid border, tint, and “To do” label instead of pushing attention to the next flight.
